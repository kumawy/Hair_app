# Face Scanner: локальная проверка

Приложение отправляет сделанный камерой снимок в существующий Python-сервис. Модель работает на компьютере; телефон показывает камеру, анкету и рекомендации. Платный API не используется.

## Запуск на iPhone / Android

1. Запустите сервер в отдельном терминале. После обновления перезапустите уже работающий сервер (`Ctrl+C`, затем команда ниже), чтобы появился endpoint `/landmarks`:

   ```sh
   ../face-shape-prediction-lab/start-local.command
   ```

2. Подключите телефон и компьютер к одной Wi-Fi сети. На телефоне откройте `http://<IP-компьютера>:8000/health`: ожидается `{"status":"ok"}`.
3. Из каталога приложения запустите:

   ```sh
   ./tool/run_local_scanner.sh
   ```

   Скрипт берёт IP интерфейса `en0` и проверяет сервер. Можно указать устройство через `-d <device-id>` и адрес явно:

   ```sh
   FACE_ANALYSIS_URL=http://192.168.1.11:8000 ./tool/run_local_scanner.sh -d <device-id>
   ```

   Эквивалент без скрипта:

   ```sh
   flutter run --dart-define=FACE_ANALYSIS_URL=http://192.168.1.11:8000
   ```

4. Откройте центральную вкладку Face Scanner или кнопку на главной странице. Разрешите камеру и доступ к локальной сети. Новые нативные разрешения требуют полного перезапуска сборки, hot reload недостаточно.

Для обычного запуска через Run в IDE debug-сборка использует локальный адрес `http://192.168.1.11:8000` из `face_analysis_config.dart`. Явный `FACE_ANALYSIS_URL` имеет приоритет; скрипт запуска автоматически подставляет текущий IP компьютера. В release/profile-сборке без `FACE_ANALYSIS_URL` остаётся ручной выбор формы. Изменение URL также требует перезапуска с новым `--dart-define`. `localhost` на физическом телефоне обозначает сам телефон.

## Сценарий

- Только съёмка камерой, без галереи и разрешения на фототеку. Белый овал мягко пульсирует; при подходящем положении лица становится зелёным.
- Живые подсказки: одно лицо, расстояние до камеры, центрирование, поворот/наклон головы, слишком тёмное лицо. Телефон нужно держать вертикально.
- Камера открывается сразу на весь экран. По умолчанию снимок делается круглой кнопкой с иконкой камеры после правильного позиционирования. Если включить Auto capture, после примерно секунды устойчивого положения камера делает снимок с тактильным откликом. Смещение, пропуск кадров или потеря лица сбрасывают отсчёт. Автосъёмку можно выключить, ручная кнопка остаётся доступной.
- После съёмки — полноэкранный просмотр, маленькая кнопка пересъёмки и отдельная кнопка «Analyze photo». Во время анализа поверх снимка показывается сетка реальных точек лица с проходом подсветки слева направо.
- Форма лица — предположение. Пользователь явно подтверждает её или выбирает другую, включая Diamond.
- Текстура и длина подставляются из профиля. Отсутствующие параметры нужно выбрать; заполненные можно изменить.
- Результат показывает выбранные параметры и до шести стрижек с совпадающими тегами формы лица и текстуры, с пояснением ограничений длины. Если совпадений мало, список не дополняется несовместимыми стрижками.
- Сохранение выполняется отдельной кнопкой для авторизованного пользователя. После сохранения обновляются профиль и рекомендации на главной странице. Гость может пройти весь сценарий без записи в Firestore и войти прямо с результата, сохранив текущий выбор. Завершённые результаты записываются в историю на устройстве без фотографий, отдельно для гостя и каждого аккаунта.

Снимок не записывается в Firestore. Клиент держит его в памяти текущего сценария; камера может использовать временные файлы платформы. Локальный сервер обрабатывает снимок без постоянного сохранения. При замене сервера необходимо отдельно проверить его политику хранения.

## Камера и анимация анализа

Камера занимает весь экран, без нижней навигации и без маски. Поверх видео остаются мягко пульсирующий овал, подсказки, переключение камеры, Auto capture и круглая кнопка съёмки. Закрытие экрана освобождает камеру. Разрешения, ошибки и ручной выбор формы доступны без работающего сервера.

После нажатия Analyze photo клиент отправляет снимок в `POST /landmarks`, затем в `POST /predict`. Первый запрос возвращает 478 точек MediaPipe и связи сетки в координатах исходного снимка после EXIF-коррекции. Фото и сетка используют одинаковый центрированный `BoxFit.cover`, поэтому линии совпадают с глазами, носом, губами и контуром лица. Плотная мятная сетка дополнена белыми анатомическими контурами глаз, губ, бровей и лица. Длинные декоративные перемычки удалены. Пока точки загружаются, по фото сразу проходит мягкая вертикальная подсветка. Подсветка проходит слева направо за 1,8 секунды; быстрый ответ модели показывается после завершения первого визуального прохода. Это анимация, а не измерение прогресса модели.

Системное уменьшение движения отключает пульсацию и движение подсветки; дополнительной задержки перед результатом нет. Если сервер не обновлён, недоступен или не смог найти точки, сканирование останавливается с понятной ошибкой и возможностью повторить запрос; ошибка получения геометрии не скрывается.

Кнопка снимка недоступна при неправильном позиционировании. Если детектор недоступен, остаётся ручная съёмка с подсказкой. На сервер отправляется только снимок после отдельного нажатия Analyze photo; видеопоток остаётся на устройстве.

## Ограничения прототипа

Модель `Diksha-cmd/face-shape-prediction`, веса `faceshape_facenet_v3.keras`. `oblong` преобразуется в `Shape.long`; ромбовидного класса в модели нет. Проценты модели не равны измеренной точности и не показываются как вероятность правильного ответа. Предупреждение о неоднозначном результате использует предварительную эвристику: максимальный score < 0.65 или разница между двумя первыми < 0.15. Высокий score также может сопровождать ошибку.

Живые подсказки работают на устройстве: [Apple Vision](https://developer.apple.com/documentation/vision/vndetectfacerectanglesrequest) на iOS и встроенная в приложение [ML Kit Face Detection](https://developers.google.com/ml-kit/vision/face-detection/android) на Android. Видеокадры не отправляются на сервер. Это проверка кадра, а не модель формы лица: она не требует запущенного Python-сервера. Канал `hair_app/live_face` возвращает нормализованные границы, углы головы в градусах и среднюю яркость внутри лица. iOS использует уже повёрнутый/зеркальный BGRA-поток камеры; Android преобразует YUV с учётом шагов строк/пикселей, вращает по ориентации сенсора и зеркалит координаты фронтальной камеры. Проверяется не более примерно 5 кадров/сек., без очереди запросов.

Пороговые значения положения и яркости — предварительные эвристики для проверки на реальных устройствах. Зелёный овал не гарантирует резкость или точность определения формы; волосы, закрывающие лоб, пока не проверяются. При недоступности живого детектора остаётся белый овал и ручная съёмка. Анимации учитывают системную настройку уменьшения движения. Ошибки `no_face`, `multiple_faces`, `side_face`, `bad_image` обрабатываются по ответу сервера.

Рекомендации строятся по редакционным тегам существующего каталога, а не другой ML-моделью: форма и текстура по 3 балла, совпадение категории длины 2, возможность более короткой стрижки 1. Баллы не показываются как точность. Советы не являются гарантией результата стрижки.

Камера ориентирована на Android/iOS; симулятор iPhone позволяет проверить ручной выбор параметров, но живую камеру и автосъёмку нужно проверять на телефоне. Android HTTP разрешён только в debug/profile. Для публикации нужен HTTPS-сервис, а также отдельная проверка модели на разнообразных людях и лицензий модели/обучающих данных.

## Архитектура и проверки

`FaceAnalysisService` отделяет экран от модели. Текущая HTTP-реализация вызывает `POST /landmarks` (до 10 секунд, геометрия сканирования), затем `POST /predict` (до 45 секунд) с multipart-полем `photo`. Размер фото ограничен 20 МБ. Чтобы перейти на другую модель или обработку на устройстве, замените реализацию провайдера `faceAnalysisServiceProvider`.

```sh
flutter analyze
flutter test
```

Опциональный сетевой тест запускается только вручную при работающем сервере (отправляет фото стрижки из каталога):

```sh
flutter test --dart-define=FACE_ANALYSIS_URL=http://127.0.0.1:8000 test/face_analysis_live_test.dart
```

## Проверка живой камеры на телефоне

Нужен полный перезапуск сборки: добавлен нативный канал, hot reload недостаточно.

1. Открыть Face Scanner: камера включается сразу на весь экран. Без лица рамка белая и слегка пульсирует. Маски и галереи нет.
2. Встать по центру, смотреть прямо, приблизить лицо до нужного размера. Рамка становится зелёной; можно нажать круглую кнопку камеры. Включить Auto capture и проверить снимок после примерно секунды неподвижности.
3. Во время отсчёта отвернуться или выйти из рамки: овал должен побелеть, автоснимок отмениться.
4. Проверить тёмную комнату, два лица, смену камеры и поворот телефона. При горизонтальном положении должна быть подсказка держать телефон вертикально.
5. Выключить Auto capture, сделать ручной снимок, нажать Retake photo. Проверить возврат назад и сворачивание/разворачивание приложения.
6. Для анализа запустить Python-сервис и нажать Analyze photo. Должна появиться сетка по реальным точкам лица и подсветка слева направо, затем подтверждение формы. Проверить совпадение сетки со снимком и режим уменьшения движения.
